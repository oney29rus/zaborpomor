## HIGH

### 1. Header-навигация ведёт на `#`

| | |
|---|---|
| **URL** | Все страницы (Header, MobileMenu) |
| **Проблема** | `NAV_LINKS`: «Заборы», «Цены», «Наши работы», «О компании» → `href="#"` |
| **Почему важно** | Плохая crawlability, бесполезные внутренние ссылки для роботов |
| **Что сделано** | — |
| **Что нужно** | Привязать к реальным URL: виды заборов → `/`, `#calculator`, опубликованные разделы |

### 2. Раздел `/raboty/` не создан

| | |
|---|---|
| **URL** | `/raboty/`, `/raboty/{slug}/` |
| **Проблема** | Страницы портфолио и карточек объектов отсутствуют |
| **Почему важно** | Потеря long-tail трафика по объектам, E-E-A-T |
| **Что сделано** | Отключены crawlable-ссылки на 404: `linkProjects={false}` на главной и страницах заборов; убрана ссылка «Смотреть все работы»; demo-отзывы без projectSlug |
| **Что нужно** | Создать `/raboty/` и динамические страницы объектов; добавить в sitemap |

### 3. Страницы заборов без локализации под районы

| | |
|---|---|
| **URL** | `/zabory/*` |
| **Проблема** | Title/H1 только «в Архангельске», без упоминания Северодvinska, районов |
| **Почему важно** | Для локального SEO в Яндексе/Google часть спроса идёт по «забор + город/район + материал» |
| **Что сделано** | — |
| **Что нужно** | Либо локальные landing по материалам, либо усилить перелинковку с городских страниц (не менять тексты массово без стратегии) |

### 4. Неполная перелинковка между городскими страницами

| | |
|---|---|
| **URL** | `/arhangelsk/`, `/severodvinsk/` |
| **Проблема** | На `/arhangelsk/` Северодvinsк и Новодvinsк в «Другие города» — `published: false` (не ссылки). Холмогоры и Приморский район не везде связаны |
| **Почему важно** | Слабее распределение ссылочного веса между geo-страницами |

### 10. `/privacy/` — заглушка

Страница с `noindex` — корректно для черновика. Перед запуском рекламы — наполнить текстом.

### 11. VK-соцсеть в footer

`href: null` — ссылка не выводится. Добавить URL группы ВКонтакте.

### 12. Trailing slash

Canonical использует trailing slash (`/arhangelsk/`). Next.js по умолчанию обрабатывает оба варианта — при деплое проверить редирект на канонический вариант на уровне хостинга.
